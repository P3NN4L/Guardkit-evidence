# messages.jsonl 取数规格（给数据侧）

> 目标：替换 `data/messages.jsonl` 为**全真实文本**（当前 160 条里 113 条含 LLM 生成成分）。
> 用途：① 课程硬门槛「≥50 条短文本」；② proposal 承诺的 60 例评估集；③ 判决卡三条演示路径的真实素材。
> 交付方式：直接覆盖 `data/messages.jsonl`，建库脚本会原样读入——格式对齐即可，无需通知代码侧改代码。

---

## 一、样本设计（要什么样的消息，按产品路径划分）

产品的三条核心路径各需要真实样本覆盖，评估节还要困难案例。**按下面四类取，总量 60–120 条**：

### A. 主骗局类（label=scam，25–35 条）
产品要拦的东西，每类至少 3–5 条，覆盖粤/英：

| # | 类别 | 说明 | 为什么需要 |
|---|---|---|---|
| A1 | **冒充供应商/客户换收款账户**（BEC） | 「我司换咗收款戶口，请今日内转账」 | 产品主故事（判决卡①的原型），必须充足 |
| A2 | 冒充老板/同事紧急转账 | CEO fraud 变体，邮件或对话体 | 同为 BEC 大类，评审会问覆盖面 |
| A3 | 假银行/官方钓鱼短信 | 带仿冒链接（.top/.xyz/仿冒域名）、假积分兑换、假冻结警告 | 练习可疑 URL 守卫与钓鱼类别 |
| A4 | 假客服/恐吓类 | 假快递、假缴费、假公检法、「账户异常否则冻结」 | 常见高发类 |
| A5 | 兼职/投资诱饵 | 刷单、高息投资群 | 引擎第三大类 |
| A6 | 冒充亲友借钱/换号 | 对话体：「我手机坏了，这是我新号」 | 与困难案例 C1 同源但**真骗局**版本 |

### B. 正常消息（label=normal，25–35 条）——**白名单放行路径的原料，缺了故事不成立**

| # | 类别 | 说明 | 为什么需要 |
|---|---|---|---|
| B1 | **银行/官方机构通知（≥12 条，必须）** | 真实月结单、账单、按揭、信用卡签账提醒、政府/医院/学校/税务局通知，带「如需查询请致电热线/App 内查看」类指引 | 白名单 R-INSTITUTIONAL/R-NOTICE 三重条件要靠它们练习「放行」；判决卡②的原型 |
| B2 | 普通日常 | 同事沟通、物流/外卖通知、营销短信、用户自己触发的 OTP | 铺「未识别风险」档位的正常分布 |
| B3 | 灰区正常（3–5 条） | 带「转账/戶口/付款」字样但真实的对账、报销、租金沟通 | 挑边界：分数偏高但属正常，评估节最有讨论价值 |

### C. 困难案例（≥10 条，label 按真值，note 标困难类型）
引擎已知盲区的真实样本——课程明确奖励「difficult cases 的 strong evaluation」：

| # | 类型 | 说明 |
|---|---|---|
| C1 | **对话体假借钱测警觉性** | W12-N16 同类（「哥，我手机坏了急用二万」其实是本人测试）——真值 normal，引擎会误报 |
| C2 | 广告类 | 贷款/推销广告——历史误报大类 |
| C3 | 单一关键词触发类 | 仅含个别敏感词的普通消息（对齐 fp-attribution 三类归因） |
| C4 | **2025–2026 新骗术** | 转数快 FPS 仿冒通知、演唱会/代购骗局等新话术——引擎有已知召回缺口，需要真实样本**如实测出**这个缺口（诚实局限的素材） |

### D. 语言分布
香港场景真实比例：**粤语 zh-HK 为主**，普通话 zh、英文 en、中英混合 mixed 各 ≥15%。

## 二、硬性红线（违反任何一条整批退回）

1. **全部真实**：`synthetic_derived` 必须为 `false`。来源限：团队盲测卷、真实标注语料池（real 标注行）、真实银行/政府通知存档、公开骗案通报原文。**LLM 改写/生成/润色一律不要**——课程申报「no AI-generated data」靠这条撑住。
2. **可溯源**：每条必须带来源卷集合 `volume` + 源 ID（能回到原库记录）。
3. **文本逐字**：`text` 保持原样，**不要清洗、改写、补标点**——打分引擎是确定性 n-gram 模型，改一个字分数就变，评估就失真。
4. **无真实个人信息**：不要出现真实人名+邮箱/电话/证件号的组合（建库有 PII 扫描，命中会记数并要求人工处理）。
5. **label 必须是真值**：用源库标注，不要自己猜；拿不准的不要。
6. **无重复**：`msg_id` 全局唯一，`text` 不得整条重复。

## 三、格式契约（JSONL，UTF-8，一行一条）

```json
{"msg_id": "n200-N07", "volume": "blind-n200", "label": "normal", "lang": "zh-HK",
 "channel": "sms", "received_at": "2026-01-15", "synthetic_derived": false,
 "kind": "real", "text": "【恆生銀行】您的信用卡賬單已於今日發出…"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `msg_id` | ✅ | 全局唯一；**禁止 `MSG-` 前缀**（演示消息保留字） |
| `text` | ✅ | 消息原文逐字 |
| `label` | ✅ | `scam` \| `normal`（真值） |
| `lang` | ✅ | `zh-HK` \| `zh` \| `en` \| `mixed` |
| `volume` | ✅ | 来源卷/集合标识（如 `blind-n200`、`real-notices`） |
| `synthetic_derived` | ✅ | 必须 `false` |
| `kind` | 建议 | `real`（或更细的来源类型） |
| `channel` | 可选 | `sms` \| `whatsapp` \| `email`（缺省落 NULL） |
| `received_at` | 可选 | 日期/时间戳（缺省落 NULL） |
| `note` | 可选 | 困难案例标注（如 `已知困难案例：对话类`） |
