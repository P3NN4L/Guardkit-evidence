## 一、目标（一句话）

在 v7 引擎之上交付一个可查验的证据型分流原型：**一条可疑支付消息 → 判决卡（分数/命中规则/官方依据原文/建议动作）→ 可升级人工**，外加 SQLite 数据底座、检索层、60 例评估集和治理文档。

**不做什么**（写进 proposal 的 Out）：不训练模型、不改引擎、不做生产部署、不做 App 集成、不做实时流。

## 二、产品形态（定死，避免范围蔓延）

- **原型载体**：Jupyter/Colab notebook 或轻量 web 页（二选一，见决策清单 #4）
- **数据库**：SQLite 单文件（marker 零配置可跑）
- **引擎接入**：npm 包 `@p3nn4l/guard-kit@7.0.0`，pinned，不改
- **核心路径**（marker 必须能亲手跑通的一条）：贴消息 → 打分落库 → 判决卡 → 点依据看官方原文 → 升级生成案件

## 四、工作包分解

### WP1 数据底座（估 2-3 天）✅ 已完成
- SQLite schema：`institutions` / `rules` / `messages` / `verdicts` / `evidence_documents`（字段见提案 §3，含 `whitelist_rule` 枚举、`generation` 标注、`model_version`）
- 从 `training/artifacts/corpus.jsonl` + 盲卷精选 ~1,000 条入池，每行补 `generation`（real/template/llm+模型名）
- 写数据字典（含生成内容标注段）+ 5 条代表性业务 SQL（如「近 30 天高危判决中命中机构白名单的比例」）
- **产出**：`guardkit_evidence.sqlite` + `docs/data-dictionary.md` + `docs/queries.sql`（另：`data/source-register.csv`、`docs/requirements-compliance.md`、课程交付 notebook）

### WP2 证据库（估 1 周）✅ 门槛版已完成（25+2 份；200 份为愿景值）
- 【前置】确认先期抓取成果（~5,000 fragments）的位置与可用性——不在 public-v7 仓
- 从 HKMA/银行/警务处防骗页精选 ~200 份，每份 JSON：原文段落列表 + URL + 抓取日期 + license 备注 + content hash
- 来源登记表（source register）+ 术语标签（机构/类别/语言）——这是检索层的地基
- **产出**：`evidence/*.json` + `source-register.csv`

### WP3 检索层（估 4-5 天）✅ 已完成（FTS5+BM25+文档聚合；embedding 经论证不采用，见 design.md §4）
- 基线：SQLite FTS / metadata 过滤（机构×日期×语言×类别）
- 增强：语义检索（embedding），只在有对比数据支撑时保留——guidelines 原话「embeddings when they add justified value」
- 检索质量评估：@k 命中率，metadata-only vs hybrid 对比表（报告的得分点）
- 失败处理：检索无结果时判决卡显示「无官方依据可引」而非硬编——本身就是一个治理设计点
- **产出**：检索实现（`src/textproc.py` + `run_demo.py` 检索段）+ 选型论证（`docs/design.md` §4）

### WP4 原型与判决卡（估 3 天）✅ 已完成（含课程交付 notebook）
- 接引擎：消息→`mlScore`→verdicts 落表（含 band、whitelist_rule、model_version）
- 判决卡：分数/档位 → 命中规则人话解释 → 检索出的官方段落（URL+日期）→ 建议动作（核实/升级）
- 升级动作：生成案件记录（判决卡全文+状态=待人工复核）
- demo 脚本：3 条固定消息（高危骗局/机构通知正常件/多轮对话铺垫）+ 兜底视频录制
- **产出**：原型 + `README.md`（运行步骤）+ demo 视频

### WP5 评估与治理（估 1 周）🟡 池子就绪（108 条+交叉表），成稿待做
- 60 例评估集：真实消息 + 团队手写案例（**不用 LLM 生成行**）；构成=常规案例 30 + 困难案例 30（双语、边界、白名单冲突、多轮铺垫）
  - 困难案例直接从现成材料抽：盲卷 W12-N16（假借钱测警觉性）、对话类 FP、广告类 FP
- expected vs observed 表 + 失败分析（含引擎已知局限：2025 新骗术召回缺口，主动写）
- 治理文档：访问分级、隐私（不存真实用户消息）、人工复核流程、版本血缘（pinned 引擎+parity 守门）
- AI 申报 + 生成数据声明的证据整理（generation 抽检记录）
- **产出**：`evaluation/60cases.csv` + 结果表 + `governance.md`

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 证据页面变更/失效 | 抓取时存快照+hash+访问日期（已写进提案） |
| 先期抓取成果找不到/不可用 | P0 就确认；fallback=WP2 改为现场抓 200 份（多 3-4 天） |
| 语义检索效果不好 | 预案就是对比设计：metadata-only 已能跑通核心路径，embedding 留作「justified value」的加分讨论 |
| 组员进度不齐 | 每周例会+贡献记录；WP2 体力活可随时加人 |
| 引擎被问「为什么置信」 | 答辩标准答案：三重白名单条件+BAD_URL 守卫+永不自动拦截+校准表（ECE）公开 |
